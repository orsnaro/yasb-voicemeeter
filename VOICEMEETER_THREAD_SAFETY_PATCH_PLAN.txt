Voicemeeter Thread-Safety Patch Plan (File-By-File)
Date: 2026-03-06

Goal
- Make current Voicemeeter integration thread-safe with minimal behavioral change first.
- Then provide migration path to dedicated worker-thread architecture.

Phase 1: Minimal Safe Patch (recommended first)

1) File: src/core/utils/widgets/voicemeeter/VoicemeeterInterface.py

A) Fix stopped call and thread start logic
- Function: `RegisterControlChangeNotify`
- Change:
  - From: `if self.vm_direct.stopped:`
  - To:   `if self.vm_direct.stopped():`
- Change:
  - Remove wrapper `threading.Thread(target=self.vm_direct.init_thread, ...)`
  - Call `self.vm_direct.init_thread()` directly inside lock/refcount gate.

B) Add synchronization primitives and counters
- Class attrs to add:
  - `_state_lock = threading.RLock()`
  - `_subscribers = 0`
- Keep or simplify:
  - `_instances_count`
  - `_watched_instances`
- Optional remove:
  - `_update_threads` (not needed after direct `init_thread()` call)

C) Refcounted register/unregister lifecycle
- Function: `RegisterControlChangeNotify(callback)`
- Steps:
  1. Acquire `_state_lock`
  2. Set `self._shared_volume_callback = callback`
  3. Add self as observer if not already tracked in `_watched_instances`
  4. Increment `_subscribers`
  5. If `_subscribers == 1`:
     - `self.vm_direct.clear_dirty()`
     - `if self.vm_direct.stopped(): self.vm_direct.init_thread()`
     - `self.vm_direct.event.add(["pdirty"])`

- Function: `UnregisterControlChangeNotify(callback)`
- Steps:
  1. Acquire `_state_lock`
  2. Remove self observer if present
  3. Clear `self._shared_volume_callback`
  4. Decrement `_subscribers` (clamp at 0)
  5. If `_subscribers == 0`:
     - `self.vm_direct.event.remove(["pdirty"])`
     - `self.vm_direct.end_thread()`

D) Guard all class/global shared state mutations
- Function targets:
  - `__new__`, `__del__`
  - `_start_vm_direct_if_not_started`, `_stop_vm_direct_if_not_stopped`
  - register/unregister methods above

E) Make callbacks defensive
- Function: `on_update`
- Keep:
  - if callback missing or cleared, return without raising
- Do not mutate UI directly here.

F) Adjust stop behavior
- Function: `stop_vm_api`
- Steps:
  1. Acquire `_state_lock`
  2. If `_subscribers > 0`: skip logout and log debug/info
  3. Else: `end_thread()` (if running) then `logout()` once

2) File: src/core/utils/widgets/voicemeeter/service.py

A) Keep current inheritance but ensure safe shutdown path
- Function: `__del__`
- Ensure it only triggers `stop_vm_api()` when appropriate and does not force shutdown with active subscribers.

B) Avoid calling VM init from background fetch thread if possible
- Function: `_initialize_audio`
- Preferred:
  - Fetch devices/speakers in fetch thread
  - Defer VM interface creation to main/service path (`get_volume_interface`) to reduce races.

3) File: src/core/utils/widgets/volume/service.py

A) Keep Qt-thread UI update bridge
- `_SharedVolumeCallback.on_notify` should only emit signal.
- `_on_volume_change` continues UI updates.

B) Optional hardening
- Guard widget list iteration with a lock or copy (copy already used).

4) File: src/core/widgets/yasb/voicemeeter.py

A) No direct thread changes required
- Continue calling service methods only.

B) Optional robustness
- In `_on_slider_value_changed`, avoid forcing `_update_label()` on every intermediate tick if noisy.

5) File: src/core/widgets/yasb/volume.py

A) Cleanup correctness issue
- Remove duplicated `toggle_mute` block at end of method.

Phase 2: Worker-Thread Architecture (recommended follow-up)

1) New File: src/core/utils/widgets/voicemeeter/vm_worker.py
- QObject moved to dedicated QThread.
- Owns `vm_direct` exclusively.
- Exposes slots for set/get/mute operations.
- Emits `changed` signal on `pdirty`.

2) File: src/core/utils/widgets/voicemeeter/service.py
- Instantiate and own worker + QThread.
- Route requests via queued signals/slots.
- Keep widget API unchanged by wrapping worker operations.

3) File: src/core/utils/widgets/voicemeeter/VoicemeeterInterface.py
- Either:
  - thin adapter over worker, or
  - deprecate in favor of service-bound worker API.

Acceptance Criteria
- No direct `vm_direct` access from multiple threads.
- No observer list mutation races during notify.
- Multiple Voicemeeter widgets/bars work concurrently.
- Clean shutdown with no hangs.
- Device change/reinit remains functional.

Suggested Commit Split
1. Commit 1: Hotfix + refcount + locking in VoicemeeterInterface
2. Commit 2: Service hardening and volume widget cleanup
3. Commit 3: Optional worker-thread migration
